# 中国大陆计薪日历

Mac 1.2.0 / Web 1.1.0 新增可选计薪口径，不自动迁移已有设置。打开「薪资排班 → 计薪口径 → 中国大陆计薪日历」并保存即可启用。

适用于按全国双休及国务院调休安排的月薪展示。当前包含已核对的 2025、2026 年。不是考勤系统、工资结算或加班工资计算器，不包含企业年假、地方节日和特殊工时制度。

## 计算

- 普通周一至周五、公告补班日：按用户常规时段工作并计薪。
- 法定带薪节日：不上班也计薪，显示「带薪休假」。收入仍在用户常规时段内累计，沿用不计薪休息扣除；这些是展示时段，不要求用户当天工作，也不发送下班提醒。
- 普通周末和调休形成的休息日：不另行累计。不能把整段长假都当作额外带薪节日。
- 单日手动安排优先：自定义工作时段替换自动规则，不重复计薪；「休息（不计薪）」移除该日开始的计薪时段，删除覆盖则恢复自动日历。跨夜按开始日期归属、收入按自然日拆分，拒绝相邻计薪时段重叠。
- 时薪 = 月薪 ÷ 当月计薪时长；完整月累计等于月薪。界面分别展示实际排班、带薪节日、计薪日和计薪时长。跨夜班的工时按月界裁剪。
- 例如 2026 年 10 月：18 个工作日 + 3 个带薪节日 = 21 个计薪日；常规每天 8 小时则为 144 小时工作、168 小时计薪。
- 这是当月收入的展示分摊方法。官方日工资折算的月平均计薪天数为 21.75；原有固定天数模式仍独立保留，小时分母使用用户常规班计薪时长，不替代实际工资核算。
- 未收录年份显示「日历待更新」，暂停自动估算并提示切回实际排班或固定口径，不使用未来预测数据。

## 来源与核对

主要来源为 [Timor 年度 API](https://timor.tech/api/holiday/)，年度地址形如 `https://timor.tech/api/holiday/year/2026/`。放假与补班日期和 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn) 的国务院公告数据交叉核对；法定带薪节日以人工核对的日期表为准，不盲信 API 的 `wage` 倍率，也不将倍率应用到普通收入。

官方依据：

- [《全国年节及纪念日放假办法》2024 年修订](https://www.gov.cn/zhengce/content/202411/content_6986380.htm)，2025 年起全体公民法定节日共 13 天。
- [2025 年放假安排](https://www.gov.cn/zhengce/content/202411/content_6986382.htm)。
- [2026 年放假安排](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)。
- [人社部门关于 21.75 天与法定带薪节日的说明](https://rsj.beijing.gov.cn/qaknowledge/202504/t20250407_4058799.html)。

本次发现 Timor 2025 年 `wage` 将 1 月 28 日除夕、10 月 6 日中秋标为 2，5 月 3 日标为 3；已按官方规则校正，修正记录保存在年度数据的 `classificationCorrections` 中。2026 年分类一致。两年每月工作 / 计薪天数及全年 13 个带薪节日均有独立预期测试。

## 更新

用户侧只读取随应用发布的静态数据；Mac 完全离线，网页不直接请求第三方日历 API，不发送工资或排班。没有后台定时任务。新年度安排公布后，先核对并补充 `data/china-statutory-days.json` 的日期，再运行：

```sh
node scripts/update-china-calendar.mjs 2025 2026
node scripts/update-china-calendar.mjs --check
npm test --prefix web
cd macos && swift run SalaryEngineChecks
```

脚本一次性抓取年度接口，拒绝缺少审核日期或公告来源、两个数据源日期不一致的结果，生成共享 JSON、网页模块和 Swift 内嵌数据。新增年份时将其加入参数并补充月度预期测试；发布网站和 Mac 新包后用户获得更新。CI 检查生成文件与源数据一致，构建和测试无需第三方 API 在线。
